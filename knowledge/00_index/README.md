# knowledge/ の歩き方

智翔館の社内知識をAIが参照できる形で置く場所。
ここ（Git 上の Markdown）が**AIが読む正本**。原本（Google ドライブ・Canva・pptx など）の場所は、
各ファイルの front matter の `source` に書く。

- 2026年11月時点で、Drive からの自動同期の仕組みは無い（設計書 `docs/knowledge-base-architecture.md` の Phase 3 で作る予定）。
  原本が更新されたら、このフォルダのファイルを直接直す
- 直したら、front matter の `updated` と `00_index/INDEX.md` も直す
- `40_要項/` だけは、要項ドキュメントから `scripts/import-yoko.mjs` で取り込む（`status: 確定` のものだけがAIに渡る）
- このフォルダはそのまま本番のアプリに同梱される。main に入れた時点で全職員のAIに反映される

## 階層

| フォルダ | 中身 | 更新責任者 |
|---|---|---|
| `00_index/` | この案内・AIへの指示・索引・用語辞書 | 安藤純平（システム担当） |
| `10_理念・方針/` | 理念、社長方針、行動指針、方針チェック観点 | 安藤純平（システム担当） |
| `20_組織・人事/` | 組織図、職務分掌、年間カレンダー | 安藤純平（システム担当） |
| `30_部門/` | 部門ごとの今期の重点・業務マニュアル・料金・カリキュラム | 安藤純平（システム担当） |
| `35_広報・制作/` | チラシ・ポスター等の制作ルール、画像生成AI用プロンプト、制作実例（入口は `チラシ制作/00_使い方.md`） | 安藤純平（システム担当） |
| `40_要項/` | 講習・テスト対策会などの要項（確定させた人を各ファイルの `owner` に書く） | 安藤純平（システム担当） |
| `50_問い合わせFAQ/` | 過去の問い合わせ回答から育てたFAQ | 安藤純平（システム担当） |
| `60_規程・手続き/` | 就業規則要約、経費精算、各種申請フロー | 安藤純平（システム担当） |
| `90_archive/` | 旧年度・統合前の原本。参照はできるが優先度は低い | 安藤純平（システム担当） |

※ 2026年11月時点では、すべてのフォルダをシステム担当の安藤純平が更新する。部門ごとに担当が決まったら、この表と各ファイルの `owner` を差し替える。
※ `20_組織・人事/`・`50_問い合わせFAQ/`・`60_規程・手続き/` はまだ空。

## 命名規約

- 数字プレフィクスで並び順を固定。間に挿せるよう10刻み
- 年度が絡むものは末尾に `_2026`
- 1ファイル1トピック。目安 200〜800行。長すぎると回答が薄まる

## front matter（全ファイル必須）

```yaml
---
title: 夏期講習会 実施要項 2026
dept: 小中等部            # 全社 / 小中等部 / RED個別 / 高等部 / LEC / 英検 / 総務
owner: 安東瑞輝           # 更新責任者
updated: 2026-06-01
source: drive:1AbcDEf...  # 原本の Drive ファイルID
source_type: spreadsheet  # doc / spreadsheet / xlsx / docx / pptx / pdf / image
tags: [夏期講習, 外部生募集, 要項]
visibility: all           # all / admin_only
summary: 2026年度夏期講習の日程・料金・外部生募集条件をまとめたもの
---
```

## 入れてはいけないもの

- 給与、人事評価、健康情報
- 生徒・保護者の個人情報（氏名、連絡先、成績の個票）
- パスワード、APIキー

これらは Git の履歴から消すのが極めて困難。必要な場合は Drive 直参照に限定する。
