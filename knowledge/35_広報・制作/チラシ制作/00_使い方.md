# チラシ・ポスター制作プロンプト 使い方と全体の流れ

画像生成AI（ChatGPT の画像生成など）で、智翔館のチラシ・ポスター・校内掲示・デジタルサイネージを作るための資料一式。
職員が手で使うことも、将来アプリが自動でプロンプトを組み立てることも想定して書いている。

## 1. ファイルの構成

| ファイル | 中身 | いつ読むか |
|---|---|---|
| 00_使い方.md（このファイル） | 全体の流れ、要項からの転記ルール、穴埋め記号 | 最初に |
| 10_デザインルール.md | 配色・文字・写真・ロゴ/QR・禁止表現。毎回プロンプトに入れる定番の指定 | 毎回 |
| 20_新規制作プロンプト.md | 新規A4チラシの基本テンプレート（11セクション）と、用途別の差し込み | 新しく作るとき |
| 30_修正・派生プロンプト.md | 部分修正・写真差し替え・文字修正・別パターン・16:9サイネージ変換・情報削減 | 直すとき・展開するとき |
| 40_チェックリスト.md | 生成前・生成後の確認項目、解像度 | 生成の前後に |
| 50_制作実例.md | 実際に作ったチラシの指定内容と結果。良い例・失敗例を貯める | 似た企画を作るとき |
| _原本/ | 統合前の元資料2点（GPT出力・Claude作成）。参照用 | 統合内容を確かめたいとき |

統合では、実際の制作で効果が確認された指定（Claude 作成の要素＝ChatGPT での制作履歴から抽出）を優先し、
GPT 出力の網羅的なテンプレートで不足を補った。両者で食い違う箇所は、各ファイルに「判断」として理由を書いている。

## 2. 制作の流れ

1. **事実を集める**：要項（status が「確定」のもの）から、チラシに載せる事実を抜き出す（→ 4. 転記ルール）
2. **メインコピーと情報の優先順位を決める**：何を一番大きく見せるかを1つに絞る
3. **プロンプトを組む**：`20_新規制作プロンプト.md` の基本テンプレートに、用途別の差し込みと `10_デザインルール.md` の定番指定を入れる
4. **生成前チェック**：`40_チェックリスト.md` の「生成前」を確認する
5. **生成**：ChatGPT の**新しいチャット**に貼り付けて画像を生成する
6. **照合**：生成画像を拡大し、文言・日付・曜日・時間・電話番号・料金を原稿と1つずつ照合する（`40_チェックリスト.md` の「生成後」）
7. **修正**：直す箇所があれば `30_修正・派生プロンプト.md` の型で、**同じ会話**に指示する
8. **仕上げ**：ロゴと QR コードは、生成後に別ツールで正式データを重ねる（AI に作らせない）
9. **印刷前の再確認**：日時・料金・電話番号をもう一度確認する
10. **展開**：必要なら 16:9 サイネージ版や別パターンを作る（`30_修正・派生プロンプト.md`）
11. **記録**：できあがったら `50_制作実例.md` に指定内容と結果を追記する

## 3. 穴埋め記号の決まり

テンプレートでは記号を次のように使い分ける。アプリで自動置換するときもこの記号を手がかりにする。

| 記号 | 意味 | 例 |
|---|---|---|
| `{{項目名}}` | 差し替える場所。プロンプトに残してはいけない | `{{講座名}}` → 定期テスト対策 |
| `【見出し】` | プロンプトのセクション見出し。そのまま残す | 【サイズ】【レイアウト｜最重要】 |
| `「　」` | チラシに載せる文言。一字一句このとおりに描かせる | 「参加無料」 |
| `# ` | プロンプト冒頭の3行タイトル、全体コンセプトのメインコピー | `# 智翔館 中等部` |

区切り線は、セクション間を `====================`、レイアウトのエリア間を `━━━━━━━━━━` とする（実制作で使った形）。

## 4. 要項からプロンプトへの転記ルール

### 4-1. 対応表

要項テンプレート（`40_要項/_TEMPLATE.md`）の各欄が、プロンプトのどこに入るか。

| 要項の欄 | プロンプトでの使い先 | 注意 |
|---|---|---|
| 講座名 | 冒頭タイトル、① ヒーローの大見出し | 正式名称のまま。略さない |
| 部門 | 冒頭タイトル1行目、配色の選択（県中対策は専用配色） | |
| 実施概要 | 【このチラシの目的】、【全体コンセプト】、② 特長の材料 | 文章をそのまま載せず、コピーに言い換える（→ 4-3） |
| 対象 | ① の対象ラベル、【このチラシの目的】 | 塾生／一般生の区別をチラシの対象に合わせる |
| 実施内容および日程（日程・時間・会場） | ③ 詳細情報 | 日付・曜日・時間は一字一句。校舎が複数なら表にする |
| 受講料 | ④ 条件 | 一般生向けチラシなら一般生の料金。税込/税抜を書く。カンマ付き（5,500円） |
| 申込開始日・申込期限・申込方法 | ④ 条件、⑤ CTA | 塾生と一般生で違う場合は、チラシの対象側だけ載せる |
| 連絡先（フリーダイヤル） | ⑤ CTA | 0120-41-1976 |
| その他（持ち物・服装など） | ④ 条件 | 長い場合は要点だけ |
| 定員・締切 | ④ 条件（載せる場合） | 「定員になり次第締切」など |

### 4-2. 守ること

- **確定した要項だけを使う。** status が「下書き」の要項から数字を拾わない（案が混ざると誤った料金・日付が印刷される）
- **原稿にない数字・文言を足さない。** 料金・日付・電話番号・住所・学校名は要項にあるものだけ
- **日付は「10月13日（火）」の形**にし、曜日を必ず確認する
- **要項どうしで食い違う情報は載せない**で担当者に確認する
  - 例：受付時間は、要項テンプレートの記載（9:30〜22:00）と全部門共通の時間（月〜土 13:00〜21:30）が食い違っているため、2026年10月時点ではチラシに載せていない

### 4-3. 制作側で作ったコピーの扱い

POINT の文言、締めのコピー、バッジの文言など、要項に無い言い回しを制作側で作るのは構わない（実例でも作っている）。
ただし事実（無料かどうか、教材費の有無、実施回数など）を含むものは、要項で裏付けが取れる範囲に限る。
作ったコピーは一覧にして、担当者の確認を受けてから印刷する。

## 5. アプリで自動化するとき（将来の実装向けメモ）

まだ実装していない。実装するときの前提をここに残す。

- **入力**：確定済みの要項1件、用途（新規チラシ／修正／サイネージ変換 など）、用途別の種類（定期テスト対策・模試・講習会・校舎イベント など）、サイズ
- **組み立て**：
  1. 要項から 4-1 の対応表に沿って事実を抜き出す
  2. `20_新規制作プロンプト.md` の基本テンプレートの `{{ }}` を埋め、用途別の差し込みを該当セクションに足す
  3. `10_デザインルール.md` の定番指定（配色・文字品質・写真・禁止事項）を入れる
  4. `{{ }}` が残っていないかを機械的に確認する
- **出力**：完成プロンプトと、別枠で「制作側で作ったコピーの一覧」「要項に無かったため空けた項目」「食い違いがあって載せなかった項目」
- **AI に任せないこと**：料金・日付・電話番号の創作、ロゴと QR コードの生成
- **参考**：`50_制作実例.md` の実例を、近い用途のお手本として AI に見せると型がぶれにくい
