# 広報制作の進め方

チラシ固有の手順（プロンプト・デザインルール）は `チラシ制作/00_使い方.md`、LPは `Web制作/30_LP制作.md`、動画は `動画制作/00_使い方.md`。ここは媒体に共通する「案件の進め方」だけを書く。

## 1. 案件フォルダの切り方

置き場所：作業用は `chishokan/work/`（Drive ID 1PFXzXncQz9zI5oGXLGxe38VTpvxSLDkZ）。終了後は `library/` へ移す（動画スキルの記載）。

フォルダ名：`YYYY-MM_案件名`（例 `2026-10_冬期講習広報物`、`2026-10_REDバス広告`、`2026-09_秋講座A4差込資料`）。YYYY-MM は着手月。

| サブフォルダ | 入れるもの | 注意 |
|---|---|---|
| `README.md` | 案件の概要と進捗メモ（2章） | 最初に作る。作業のたびに追記 |
| `00_資料/` | 受け取った要項・原稿・申込書・ロゴ・前回デザイン・写真 | **直接直さない**。直すときはコピーを `02_制作/` に作る |
| `01_原稿/` | 要素データ（要項から抜き出した事実）、コピー案、確認文面、工程表、台本、引き継ぎメモ | 事実の出典をファイル冒頭に書く |
| `02_制作/` | プロンプト、生成画像、HTML・スクリプト、試作 | 版ごとに残す |
| `03_納品/` | 確定版（PDF・PNG・MP4・入稿データ） | 媒体別に `01_チラシ/` `02_ポスター/` `03_サイネージ/` などに分ける例あり |
| `04_web掲載/` | Web用に変換した動画・サムネイル・WordPressブロックの控え | 動画案件で使用 |
| `_削除用/`、`_旧_◯◯版/` | 使わなくなった版 | すぐ消さず退避。中身を確かめてから削除 |

- 生徒の個人情報（成績・名簿）は案件フォルダに置かない。Drive の `07_名簿成績出席`（限定共有）に置き、案件側には原稿・構成案だけを置く（LP成績アップ素材の README のルール）。
- 納品データの最終置き場は案件フォルダの `03_納品/` と、Drive `05_広告制作/YYYYMMDD_案件名_納品データ/` の2系統がある〔要確認：どちらを正本とするかの決まり。冬期講習・高専は 05_広告制作 側にも納品データあり〕。

## 2. 案件README の項目（templates/案件README.md）

| 項目 | 書くこと |
|---|---|
| 目的 | 何のための制作物か（例「一般生の申込を集める」） |
| ターゲット | 学年・塾生／一般生・保護者 |
| 使用媒体・サイズ | チラシA4表裏、ポスターA1、サイネージ16:9 など |
| 掲載場所 | 校舎内／校舎外／パンフ差し込み／Web |
| 公開・実施日 | 申込開始日・実施日 |
| 制作期限 | 納品希望日（要項） |
| 最重要メッセージ | 一番大きく見せる1点 |
| 必須情報 | 講座名・対象・日程・会場・料金・申込方法と期限・連絡先 |
| CTA | 塾生（GROWアプリ）／一般生（HP・QR）／電話 |
| KPI | 申込数など。目標が決まっていなければ〔要確認〕 |

続けて「関連URL」（要項の正本、Driveフォルダ、公開先LP）、「既存素材」、「決まったこと（日付・誰の判断か）」、「進捗メモ（日付ごと）」、「実施結果（終了後に目標と実績）」を置く。

進捗メモの書き方（各案件で共通していた型）
- 日付 → やったこと → 出力ファイル名 → 照合結果（原稿どおりか）→ 未了・要確認。
- 判断した人を書く（「安藤さん：裏面OK」「担当の修正」）。
- 保存・ダウンロードの有無も書く（「画像の保存は未了」）。

## 3. ファイルの命名と版

- 形式：`YYYYMMDD_案件名_種類_vN.拡張子`（例 `20261028_冬期講習広報物_ポスターA1プロンプト_v1.md`、`20261104_東翔高校定期演奏会広告_写真版A_角ゴシック_v1.pdf`）。
- 日付は作成日。版は v1, v2… と上げ、**前の版は消さない**。
- 差し替えた素材は末尾に `_旧`（例 `音声_09_旧.mp3`、`音声_10_旧_三者面談版.mp3`）。
- 案を並べるときは `_案1` `_案2`、`_A` `_B` で区別し、採用した案を README に書く。
- 元の名前が中身と合わないファイル（例：AI生成ツールの自動名）は、中身に合わせて改名し、元の名前を README に控える。

## 4. 制作の流れ（全媒体共通）

| 工程 | やること | 出力 |
|---|---|---|
| 1 依頼の確認 | 要項（status＝確定）を読み、作る媒体・期限・確認者を確かめる | README |
| 2 要素データ | 要項から日付・料金・会場・申込方法を抜き出す。食い違い（曜日・受付時間・LPとの差）は表にして報告 | `01_原稿/…_要素データ_v1.md` |
| 3 工程表 | 制作依頼→初稿→担当チェック→修正・展開→LP・QR→納品→公開→申込開始→締切→実施 を日付で並べる | `01_原稿/…_工程表と確認文面_v1.md` |
| 4 初稿 | 1媒体（多くはチラシ）で形を決め、承認後に同じ会話・同じ型でポスター・サイネージ・LPへ広げる | `02_制作/` |
| 5 照合 | 生成物を拡大して、文言・日付・曜日・時間・金額・電話番号を原稿と1つずつ照合 | README に結果 |
| 6 担当確認 | 確認文面を作り、送るのは安藤さん（LINE WORKS）。確認してほしい点を番号付きで3つ程度に絞る | 確認文面 |
| 7 修正 | 指摘を「画面（見た目）の修正」と「原稿（文言）の修正」に分けて反映 | vN+1 |
| 8 納品 | `03_納品/` に保存し、README に最新版のファイル名を書く。ロゴ・QRの合成が残っていれば明記 | 納品データ |

決まりごと
- **事実の正は要項（または facts.csv の状態＝確定の行）**。LPや前年の資料と食い違えば要項を使い、差を報告する（冬期講習 2026-10-28 の決定）。未確定は〔要確認〕のまま残し、推測で埋めない。
- **要項にない文言は「私が書いた文言」として一覧にする**（キャッチ、こんな人におすすめ、POINT説明、FAQ）。担当の確認が取れないものは載せない。
- 曜日は暦で確かめる（python の calendar で確認した例あり）。要項の誤記の可能性があれば、正しいと思う方で作って確認事項に挙げる（高専「12月20日（土）」→（日））。
- 受付時間は要項ごとに違うため、全部門共通の時間を使う（2026-10-16 決定）。
- ログイン・ダウンロード・送信は本人（安藤さん）が行う。AIはダウンロード前に保存元・ファイル名・大きさを伝えて了承を得る。

確認文面の型（高専攻略講座の例から）
```
◯◯先生
◯◯のチラシ（表・裏の2ページ）の初稿ができました。添付をご確認ください。
確認をお願いしたい点は3つです。
① （要項と暦・共通ルールの食い違い）
② こちらで書いた文言（一覧）
③ （受講の形・載せ方の確認）
◯月◯日（◯）までにお返事をいただけると助かります。
このあと同じデザインでポスター・サイネージ・LPを作ります。
```

## 5. 広報の年間・月間の進行管理（広報ロードマップ）

2026年9〜10月は「1週＝1行」の表で管理した（drive:1Fj9V8gF_zDVBenkj9L2F_JLgvYpBzlPv）。

| 項目 | 内容 |
|---|---|
| 行 | 週（月曜始まり） |
| 列 | 週／期間／フェーズ／備考 ＋ 大区分3（県中コース・中等部・その他）× 中区分3（秋講座・模試・体験 など） |
| セルの書き方 | 担当記号＋施策名／制作物／締切（例「◆ チラシ 完了 9/2」） |
| 担当記号 | ★ 死守デッドライン／◆ NEP広報マーケ／◇ 現場（県中・中等部職員） |
| 表の下 | 数字目標サマリー、役割分担の原則、前提、成功の前提条件、確定待ち |
| 日程の割り当て | 配布開始日・LP納品日から逆算（例：冬季LP 構成9/24〜29 → デザイン10/8〜13 → 納品10/30） |
| 正本 | xlsx を正とし、Google スプレッドシートには CSV を貼り直して色付けGAS（formatRoadmap）を実行。Drive連携ツールではスプレッドシートを上書きできないため |

講座ごとの広報日程は、全社の「月間スケジュール一覧（日付横×部門縦）」の広報行に、完成・納品・公開・締切だけを書く（高専の例）。

## 6. templates の雛形（chishokan/templates）

| ファイル | 中身 | 使う場面 |
|---|---|---|
| `案件README.md` | 2章の表＋関連URL・既存素材・進捗メモ・実施結果 | 案件を始めるとき |
| `A4差込資料_画像生成プロンプト雛形.md` | パンフ差し込みA4（スケジュール・料金・申込）の画像生成プロンプト。A4比率の厳守、紙面配分、STEP色分け、優先順位1〜10、収まらないときの削る順、NG | 差し込み資料（`チラシ制作/52_制作実例_広告・ポスター.md` の9） |
| `wp-section.html` | WordPressカスタムHTMLのセクション雛形。PREFIX を案件名に置換、CSSは `.PREFIX` 配下に限定、`*` セレクタと `!important` は使わない。ヒーロー（濃紺地・オレンジのCTAボタン）＋本文（共感・課題→解決策→特徴→成果→料金→FAQ→CTA） | LPの部品（`Web制作/31_LP制作実例_追記.md`） |
| `要項テンプレート_Googleドキュメント用.md` | 講座担当が実施要項を書く雛形の控え。本体はGoogleドキュメント「_要項テンプレート（記入用）」 | 要項の項目を確かめるとき |
| `image-prompt.md`、`sesaku-table.md` | 画像生成プロンプト雛形、施策提案表の雛形（README に記載） | 〔要確認：templates フォルダに見当たらない〕 |

雛形を新しく作ったら templates に置き、CLAUDE.md のディレクトリ構成に追記する（templates/README の決まり）。

## 7. デザイン改善の確認順（docs/04-design.md）

既存デザインを直すときは、作り直す前に次の順で見る：情報階層 → タイトルサイズ → コピー → 余白 → 写真 → 色 → CTA → QR → 視線誘導。

情報階層：LEVEL1 タイトル／商品名、LEVEL2 メインコピー、LEVEL3 メリット・成果、LEVEL4 日程・対象・料金、LEVEL5 CTA・QR・問い合わせ。コピーがタイトルより目立つのが典型的な失敗（例：「おはよう勉強会」の広告で、コピーより活動名を一番認識しやすくする）。
