# 講座LP 制作実例の追記

構成の型・フォーム・QR・公開前チェックは `30_LP制作.md`。ここはそこに無い実例と素材の扱いだけ。

## 1. 前回LPを複製してブロック版の下書きを作る（高専攻略講座 2026-10）

| 順 | やったこと | 注意 |
|---|---|---|
| 1 | 定期テスト対策のキャンペーン投稿を「新規下書き」で複製し、高専攻略講座用に書き換えて下書き保存（未公開） | 本文の控えを `02_制作/…_LP本文_WPブロック_v1.html` に保存。保存後にブロック数と「無効なブロックなし」を確かめる |
| 2 | 前回固有のブロックを外す：メイン画像、定期テストの実績ブロック、定期テスト用の申込フォーム | フォームの位置には「準備中」の1行を置く（今回用フォームができるまで） |
| 3 | 残りの作業を README に列挙：メイン画像とアイキャッチ（前回の画像のまま）、スラッグ、AIOSEO の説明文とキーフレーズ、今回用フォーム、パスワード保護の要否 | 前回の画像が残ったまま公開しない |
| 4 | スラッグ（`kosen-koryaku-2026`）を設定 → このURLで utm 付きQRを作成（チラシ・ポスター校舎内・校舎外・サイネージの4種） | QRはスラッグ確定後に作る |
| 5 | LP下書きHTMLに全部門共通の受付時間を追加 | 要項の受付時間（9:30〜22:00）は使わない |
| 6 | 「3つのPOINT」に導入文1段落と説明文3つを追加（2章のリサーチから） | すべて制作側の文言 → 講座担当の確認が要る |
| 7 | LPのメイン画像（16:9・1672×941px）を、チラシと同じ ChatGPT の会話で生成（QR枠・電話・ロゴ余白なし） | ダウンロードとWordPressへのアップロード、アイキャッチ差し替えは本人 |

その後、先頭に本番レベル模試LPと同じ型のヒーローを追加した経緯は `30_LP制作.md` 9章。

## 2. POINT説明文のための訴求リサーチ（高専攻略講座）

進め方
1. 全国の同種講座（高専受験の塾・予備校）が何を訴えているかを Web 検索で集め、「訴求の軸」ごとに表にする（今回は検索6回・ページ取得2件）。塾側のページは宣伝で、数字は各社の自己申告と注記する。
2. 公式情報（国立高等専門学校機構など）で裏付けが取れた事実だけを分ける。
3. 裏付けが取れなかったことは「広報物には使わない」と明記する。
4. 要項の講座内容と重なる訴求だけを選び、メッセージ案を3つ程度に絞る。
5. LPに入れる文言（導入文・POINT説明文）を書き、講座担当に確認してほしい点（実際の授業の進め方と合うか等）を添える。

今回の結果

| 区分 | 内容 |
|---|---|
| 公式で裏付けが取れた | 国立高専の学力検査はマークシート方式（平成28年度入学者選抜から）。5教科で、機構が統一の問題を作成。過去問題と解答用紙は機構のサイトで公開 |
| 使わなかった | 佐世保高専の傾斜配点（学校ごとに違い、裏付けなし）、「問題数が多い」「頻出パターン」（塾の解説で公式ではない）、合格実績・合格率（要項に無い）、他塾との比較 |
| 採用したメッセージ | ①高専の入試は公立高校入試とは別の試験 ②マークシートは部分点がない、だから解き直しが効く（コピー「過去問を、解きっぱなしにしない。」の理由づけ）③過去問は、いつまでに何年分を、どう直すか（個別アドバイスの中身） |
| LPの導入文 | 「国立高専の入試は、長崎県の公立高校入試とは別の『国立高等専門学校 入学者選抜学力検査』です。解答はマークシート方式。高専に合わせた準備が、合格への近道です。」 |
| 確認事項 | 説明文の言い換えが授業の実際と合うか、予想問題がマークシート形式か（違えば「本番と同じ形式に慣れていきます」を外す） |

ファイル：`01_原稿/20261009_高専攻略講座広報物_訴求リサーチとPOINT説明文_v1.md`（出典URL一覧つき）。

## 3. LPに載せる成績アップ実績の選び方（LP成績アップ素材 2026-08）

目的：LPの「成績アップ実績」に載せる生徒を、模試データと合否実績で裏を取って選ぶ（中3＝長崎県一斉模試・定期テスト、小6＝県立中受検の塾内模試）。

個人情報の扱い
- 実データ・候補一覧は Drive `07_名簿成績出席`（限定共有）にだけ置く。案件フォルダには原稿・コピー・構成案など個人情報を含まないものだけを置く。
- 実名・写真の掲載は保護者の同意が必須。同意がなければ「S.Oさん（中3・佐世保駅前校）」の形にする。
- 掲載する生徒が決まってから同意を取る。

候補の判定（候補一覧の判定欄）

| 判定 | 意味 |
|---|---|
| ◎ | 成績アップと合格の両方が確認でき、掲載可 |
| △ | どちらか一方だけ確認 |
| × | 合否一覧に記載がなく掲載不可 |
| S（定期テスト） | 伸び・高得点・合格がすべてそろう |

定期テストの抽出条件：「合計+20点以上の伸び」「5科450点以上」「いずれかの教科で100点」「1教科+30点以上の伸び」のいずれか。

数字の注意（README の「分析するときの注意」）
1. 中3の秋の模試は得点が出やすい回があり、得点は上がっても偏差値は下がる生徒が多かった → 「◯点アップ」は使わず、偏差値・県内順位・判定・合格実績で訴える。
2. 県中の塾内模試の偏差値は塾内（約50名）の母集団で出したもので、県内偏差値ではない → 「偏差値+◯」と書くと誤認される。塾内順位や本番得点で訴える。
3. 作文は採点のぶれが大きい → 作文単独の「◯◯アップ」は避ける。
4. 定期テストは第2回の方が難しく、全体では平均が下がっていた → 「塾生平均◯点アップ」は事実に反するので書かない。個人の伸びで訴える。学年・校舎で差が大きく、伸びが出ない層（中1など）は高得点で拾う。校舎別の平均は、分析時点で平均が上がっていた1校舎だけ「出せる」とされ、平均が下がった校舎の数字は出さない扱いだった〔要確認：1校舎だけの平均を載せると全体の印象を誤らせないか、載せる方針〕。
5. 模試の判定と実際の受験校は一致しないことが多い（志望変更・県外進学）→ 必ず合格結果一覧と突き合わせてから書く。
6. 合格結果一覧に見当たらない生徒（入力漏れか退塾か）は校舎に確認してから使う。
7. 候補CSVの末尾に前提・注意事項の行がある。使う前に必ず読む。

データの扱いのメモ
- 模試の集計CSVは Shift_JIS（CP932）。Python では `encoding='cp932'`。
- 定期テストの書き出しは同じものが複数世代あるため、最も新しく埋まっている版を使う。
- 中身と名前が食い違うファイル（「県中」の語が無い、別月の中身）は実態に合わせて改名した。ファイルIDは変わらないので既存リンクは生きる。

## 4. 要項とLPの食い違いの扱い（冬期講習 2026-10）

- LP（承認済み）を先に作り、後から要項が変わる場合がある（おはよう勉強会の料金・日程、テストの料金、申込期限、講座の有無で5件）。
- チラシ・ポスターは要項を正として作り、差を一覧にして報告した。LP側も要項に合わせて直す対象〔要確認：LPの修正状況〕。
- LPにある実績（合格者の成績変化、指導年数）、保護者・生徒の声は、facts で確かめられるまで他の媒体へ流用しない。

## 5. wp-section.html 雛形（templates）

- WordPress カスタムHTML用のセクション雛形。`PREFIX`（例 `aki2026`）を案件名に一括置換して使う。
- CSS は `.PREFIX` の中だけに効かせる。`*` セレクタ（`.PREFIX *` を除く）と `!important` は使わない。
- 変数：`--navy:#0F2547`、`--accent:#F08300`（オレンジのCTAボタン、角丸8px）、`--base:#FFFFFF`。見出しは `clamp()` で画面幅に合わせる。600px以下で余白を縮める。
- 中身：ヒーロー（濃紺地・中央寄せ・タイトル・メインコピー・CTAボタン `#form` へ）＋本文（最大幅880px）。本文の並びの目安は「共感・課題 → 解決策 → 特徴 → 成果 → 料金 → FAQ → CTA」。
- 2026年秋のカスタムHTML版LP（`#cks-lp`、幅960px中央、ブルーのボタン）とは色・幅が違う。新しく作るときはどちらに合わせるかを決める〔要確認：雛形を `../デザインシステム.md` の値に更新するか〕。

## 6. 動画の再生ページ（WordPress 固定ページ）

講座の説明動画を、YouTubeを使わず智翔館サイトの固定ページで見せた例（RED・ネクスタの中3冬期講習説明動画、2026-10）。

| 項目 | 内容 |
|---|---|
| ページ | 固定ページを下書きで作成。スラッグは `red-winter-2026-chu3`、`nexta-winter-2026-chu3` |
| 本文 | カスタムHTMLブロック1つ（`<video>`、`controlslist="nodownload"`、右クリック無効、再生前のサムネイル）。控えを案件フォルダの `04_web掲載/` に保存 |
| 動画 | 50MBの上限に収まるよう 1280×720・600kbps に変換してメディアに登録（本人がアップロード） |
| 確認 | アップロード後のバイト数が手元と一致するか、プレビューで再生・長さ・最後の画面・サムネイル |
| 重複 | 誤って同じ画像を複数回アップロードした例あり。使うIDを控え、重複分の削除は本人 |
| 公開範囲 | パスワード付き・検索除外・メニュー非掲載を検討。保護者への案内方法とあわせて決める〔要確認：決定内容〕 |

詳しい変換手順は `../動画制作/00_使い方.md` 8章。
