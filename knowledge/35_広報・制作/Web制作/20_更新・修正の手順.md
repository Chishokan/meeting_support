# Webサイトの更新・修正の手順

ログイン情報（URL・ユーザー名・パスワード）はここに書かない。本人が管理し、本人がログインする。

## 1. 修正の基本の流れ

| 順 | やること | 注意 |
|---|---|---|
| 1 | 直すページのURLと、直す箇所・正しい内容を確かめる | 要項・最新のチラシと突き合わせる |
| 2 | 公開中か下書きかを確かめる | 公開中なら、明らかな誤り以外は案を出して了承を得る |
| 3 | 変更前の画面を保存する | 後で見比べるため |
| 4 | 管理画面で編集する | 文字列を置き換えたら、ブロックが壊れていないかを確かめてから保存 |
| 5 | 表側をPCとスマホで確認する | 崩れ、リンク切れ、電話番号のリンク |
| 6 | フォームがあるページは送信テストを本人が行う | 自動返信・通知メール・台帳・Googleシートまで届くか |
| 7 | 何を直したかを報告する | 直した箇所、未確認の点 |

## 2. よくある修正

| 修正 | 手順・ポイント |
|---|---|
| 受付時間・電話番号 | 全部門共通「月〜土 13:00〜21:30（日・祝を除く）」、0120-41-1976。古い「9:30〜22:00」はLP・フォームの自動返信にも残りやすい |
| 講座LPの文言 | `30_LP制作.md`。担当の修正指示（赤字PDFなど）は一覧にして、チラシ・ポスター・サイネージ・LPのすべてに反映したかを1件ずつ確認 |
| パスワード保護での限定公開 | 担当確認用に「パスワード保護」で公開し、確認後に外す。パスワードは担当者が指定し、文書に残さない。編集画面から保存したときに保護が外れた例がある（2026-10-23）→保存後に未ログインのブラウザで確認 |
| アイキャッチ | 一覧カードでは1.85:1で中央を切り抜かれる。文字は上下の余白の内側に収める |
| 画像 | 公開用はJPEGでメディアに登録し、代替テキストを入れる。生成画像には「※画像はイメージです」 |

## 3. トップのスライダーバナーを差し替える（Smart Slider 3）

出典：制作会社のマニュアル「スライド編集マニュアル（智翔館様HP）」（drive:1q8pUOac-T8KRUm8ACiL0emjYM8-J5iic2rN4tOLbfKM）。

1. 管理画面の左メニュー「Smart Slider」を開く。
2. 編集するスライダーの「編集」を押す。
3. 差し替えるバナーの「編集」を押す。
4. バナーの上の「スライド」を押してスライド編集画面を開く。
5. 「スタイル」タブの画像の右「＋」を押す。
6. 新しいバナー画像を選び、右下の「選択」。
7. 「コンテンツ」タブの「リンク」にリンク先を入れる。
8. 右上の「保存」。

注意
- バナーが1枚だけのときは自動再生をオフ。2枚以上ならオン。
- 非公開のバナーは、バナーを右クリック→公開に切り替える。
- 元のマニュアルにはログイン情報が平文で書かれている。共有範囲に注意し、パスワードを変更したうえで記載を消すことを推奨〔要確認：安藤さん判断〕。

## 4. WordPress本体・プラグイン・PHPの更新

出典：artifact「智翔館WordPress PHP更新手順書」（2026-10-23実施）。

### 大原則

- 本体とプラグインを古いPHPのまま先に更新し、最後にPHPを上げる。逆順にすると古いプラグインがPHP 8でエラーになり、サイトが止まる。
- 1つ（1組）更新したら、表側とフォームを確認してから次へ。まとめて更新すると原因が分からない。
- 作業は問い合わせが少ない夜間か休校日。目安2〜3時間（バックアップ除く）。本部・教室に事前に伝える。

### 事前準備

- [ ] サーバーパネルの自動バックアップに前日分（ファイル・データベース）があるか
- [ ] All-in-One WP Migration で書き出してPCに保存（サイトは約20.7GB。書き出しが終わらないときは「バックアップファイルを除外」）
- [ ] 作業前の画面を保存：トップ、校舎ページ、ブログ記事、各フォームページ
- [ ] Snow Monkey のライセンスキーが有効か（テーマ更新に必要）

### 手順

| 手順 | 内容 | 確認 |
|---|---|---|
| 1 更新の停止を解除 | 「Disable All WordPress Updates」を停止→ダッシュボード→更新→再確認 | 更新が一覧に出る |
| 2 本体を更新 | WordPress本体を最新へ。データベース更新を求められたら実行 | トップ・ブログが表示、編集画面が開く |
| 3 プラグイン・テーマ（PHPはそのまま） | 組ごとに更新：A 必須（古いPHPで止まるもの）→B Snow Monkey（テーマ→Blocks→Editor）→C 土台（ACF、CPT UI、権限系）→D SEO・転送・メール→E その他 | 組ごとに表側。Bはスマホ表示、Cはカスタム投稿の一覧、Dはテストメール |
| 3の例外 | Contact Form 7 とその追加機能、Better Search Replace、Post Type Switcher は新しいPHPが必要なので後回し | CF7の追加機能だけ先に上げるとフォームが止まる |
| 4 PHPを切替 | サーバーパネル→PHP Ver.切替→ドメインを選び新しい版へ。数分待ちサイトヘルスで確認 | トップ・校舎・ブログが表示、管理画面、フォーム表示、バックアッププラグインの画面 |
| 4の注意 | .htaccess に旧PHPを固定する行（`myphp-script`、`php74`）が残っていると切り替わらない。該当行を消す | 同じサーバーの採用サイトも一緒に切り替わる |
| 5 残りを更新 | CF7→CF7の追加機能→残り2つ→「Disable All WordPress Updates」を削除 | 下の最終確認 |

### 最終確認

- [ ] 問い合わせフォームを実際に送信し、自動返信メールが届く
- [ ] 問い合わせ管理台帳（Webhook）とGoogleシートに入る
- [ ] 校舎の振り分け（your-campus）と条件付き項目が動く
- [ ] 送信後にサンクスページへ移る
- [ ] サイトヘルスに新しい「重大な問題」がない
- [ ] スマホでトップ・校舎・フォームが崩れない
- [ ] 作業後にもう一度バックアップ
- [ ] 本部・教室に完了を連絡

### 更新の頻度

2023年から更新が止まっていた。月初に管理画面の「更新」を見て、バックアップを取ってから更新する案〔要確認：担当と頻度は未決定〕。

## 5. トラブル時の戻し方

軽いものから順に。

| 症状 | 打つ手 |
|---|---|
| PHP切替後に真っ白、「重大なエラー」 | サーバーパネルでPHPを元の版に戻す（数分で戻る） |
| 特定のプラグイン更新後に崩れた（管理画面は開く） | そのプラグインを停止して原因を調べる |
| 管理画面も開かない | サーバーパネルのファイル管理で `wp/wp-content/plugins/` の該当フォルダ名を変える（例 `contact-form-7` → `contact-form-7_off`）。そのプラグインだけ止まる |
| 原因不明、全体がおかしい | サーバーパネルの「バックアップ」から作業前日のファイルとデータベースを復元 |

- 原因が分からないときは、管理者宛ての「サイトで技術的な問題が発生しています」メールを見る（プラグイン名が書かれている）。管理者メールは現在保守会社宛て〔要確認〕。

## 6. REST APIでの作業（システム担当向け）

- 管理画面にログインしなくても、`12_開発ツール/blog_pipeline/wp_draft.py` の関数（アプリケーションパスワードを使う）でREST APIから下書きを作れる。アプリケーションパスワードは環境変数で扱い、文書・チャットに書かない。
- Contact Form 7 はREST APIで読めるが、新規作成（POST）はエラーなしで保存されない（2026-10-19確認）。フォームの複製は管理画面で行い、書き換えはAPIでもよい。
