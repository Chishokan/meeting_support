# スライドを作る

## 手順

1. **種類と条件を決める**：`10_構成と表記のルール.md` の「1. 構成の型」から種類（社内会議／研修・活動報告／保護者・生徒向け／外部発表）を選ぶ
   - 言われていなければ既定で進める：社内会議、発表10分、8枚以内。既定にしたものは「確認してほしいこと」に書く
2. **材料を集める**：数値は、職員が渡した資料か、ナレッジ（`30_部門/振り返り/`・部門の第36期計画など）から取り、出典と時点を付ける。無い数値は〔要確認〕にして、作らない
   - 講座・テスト・特典を案内する枚があれば、`40_要項/` の確定版を必ず読む（日程・時間・会場・受講料・割引・申込・締切・対象外）。
     台本や下書きが「要項は未読」「〔要確認〕」としていても、要項があれば差し込む。要項に「と表記する」とある文はそのまま使う
   - **台本・原稿から作るとき**：台本の「話すこと」は発表者ノートへ、スライドには要点だけ。台本の〔要確認〕は「確認してほしいこと」に移し、スライドでは「◯月◯日」のように空ける
   - 保護者・生徒向けセミナーは `10_構成と表記のルール.md` の「1-3」を使う。中1・2向けと中3向けで流れが違う（中1・2は学習習慣・勉強体力と面談の約束が主）
3. **流れの表を作る**（1回目の回答）：1枚ごとに「見出し＝言いたいこと1文」「要点」「出典」。最後に、次へ進むかを選択肢で聞く
4. **Google スライドを作る**（「この流れで作る」と言われたら）
   1. `get_slide_templates` でひな形の一覧を見て、**見た目（色・書体・雰囲気）**が用途に近いひな形を1つ選ぶ（社内会議・計画なら企画書のひな形、生徒・保護者向けならセミナーのひな形）。
      生徒・保護者向けのセミナー・説明会は、ひな形「セミナー（ブルー型・生徒・保護者向け）」を第一に使う（14枚が1枚ずつ違う型。`15_見やすいスライドの型.md` の「ひな形」）。
      このひな形の枚を from で使うときは、必ず notes（話すこと）を入れる（入れないと、ひな形の「【型：…】」の説明が残る）
      **中身がぴったり合うひな形が無くても止めない**（「合うひな形が無い」と聞き返さない）。ひな形は見た目の参考にする
   2. 選んだひな形の名前を渡して、スライドごとの枠（key・見本の文字・目安の文字数）と見た目を見る
   3. 流れの表の1枚ずつに、組み方を決める（1つのファイルで混ぜてよい）
      - **from**：ひな形の枚をそのまま使う。見本の文字・枠の数が内容とぴったり合う枚（表紙、同じ型の報告の枚など）だけ。見本の文字はすべて書き換え、目安の文字数に収める。表は行を増減してよい。数字だけの枠（ページ番号）は並べた順に振り直す
      - **layout**：ひな形の見た目（背景・見出しの位置と飾り・書体・色・ロゴ）のまま、自由に組む。見本の文字が内容と合わない枚は、こちらにする
        | layout | 使う場面 | 書くもの |
        |---|---|---|
        | title | 表紙・結び | title・lead（副題）・points（日付・名前） |
        | section | 章の扉 | title・lead |
        | message | 承認・テーマ・まとめなど、大きな一言 | label（上の小さな見出し）・title（一言）・lead・points（下の淡い地の囲みに入れる要点1〜4） |
        | bullets | 要点の箇条書き（8つまで） | title・lead・points |
        | columns | 3つの力・3つの手順など、並べて比べる（カード2〜4枚） | title・lead・columns（title と text） |
        | table | 日程・料金・数値（12行・6列まで） | title・lead・table（1行目が見出し） |
        | image | 挿絵・写真のようなイメージを見せる | title・lead・image・points（左に並べる要点。省くと画像を大きく） |
        base を省くと、表紙は0枚目、ほかは見出しのある枚の見た目を使う。文字の大きさはアプリが枠に合わせる（長すぎる文は短くする）
      - **似た配置を続けない**（2026-11-19 職員の指摘：カードが並ぶ枚が4〜7枚目で続き、見づらかった）：
        columns（カード）の枚は2枚続けない。カード・箱が横に並ぶ枚（columns、カードで組んだ図）は、あいだに message・bullets・table を1枚以上はさむ。
        どの組み方も3枚続けない。続けて出すとアプリが作らずに理由を返すので、流れの表の段階で組み方の列を見て散らす
      - **見やすいと言われた形**：小さな色のラベル（例「本日のテーマ」「智翔館のTOP10文化」）→ 中央に大きな一言（1〜2行）→ 淡い地の囲みに理念や要点（箇条書き3つまで）。
        message の label と points で作る
      - **組み方の目安**（夢・志セミナー 中1・2、14枚）：表紙 title → 承認 message → テーマ・理念 message（label＋囲み）→ 問いかけ bullets → 3つの力 columns →
        学年の流れ table → ワーク message（囲みに書き込み欄）→ TOP10文化 message（label＋囲み）→ 結果の見方 bullets → 特典 columns（中1・中2）→
        講座の日程・内容 table → 受講料・申込 table → 今日決めること columns（番号つき3枚）→ 結び message（理念の一言・問い合わせ先）
      - **ひな形の挿絵の中身**を確かめる：挿絵が別の話題（例：「中3セミナー②」の脳のイラスト）なら、その枚は from で使わず、layout で組む。差し色（オレンジなど）は一語・一か所だけ
      - **背景・地の色を塗り切る**（2026-11-19 職員の指摘：背景の色が塗られていない枚があった）：どの枚もひな形の背景をページ全体に使う。
        カード・囲みの地は、中の文字と同じ位置・大きさ（文字が地からはみ出さない）。表は見出しの行も含めて全部の行に地の色を塗る
      - **箇条書きの行間**：行と行のあいだを文字の大きさの0.6倍ほど開ける（詰まって見えると言われた）
      - **見やすい型（ブルー型）**（2026-11-19 職員が選んだ形。`15_見やすいスライドの型.md`）：1枚に言いたいことは1つ、並べる要素は3〜4個、1項目は1〜2行（1行12〜15字）。
        上から「ラベルか見出し → 主役（大きな一言・図・カード・表）→ 淡い地のまとめの帯（キーワードは「」付き）」。長い説明は発表者ノートへ。
        明るい枚が続いたら、問いかけや大きな一言だけの枚をはさむ
      - **書体は Noto Sans JP**（職員の指定）。アプリが全部の文字を Noto Sans JP にそろえるので、書体は指定しなくてよい
      - **挿絵・背景の画像**：GPT・Gemini の API を使った画像生成は調整中で使えない（2026-11-19 から停止）。職員が「イラストを入れて」「背景に画像を」と頼んだら、
        `propose_nep_request`（kind：スライドの挿絵・背景、size：16:9 や 4:3 と枚数、content：どの枚に何を・どれくらい薄く）で NEP への作成依頼の案を出す。
        文字の入った画像にしない（文字はスライドの文字で書く）。実在の人物の顔・他社のロゴは描かせない。届いた画像は職員がスライドに入れる
   4. `create_google_slides` で作る。発表者ノートに話すことを書く
   - ロゴはアプリが入れる。ロゴの文字や画像は指定しない
   - 「おまかせ」「一気に作って」と言われたら、3 と 4 を1回で進める
   - 「文書にして」と言われたら `create_google_doc` で Google ドキュメントにする
5. **仕上げの確認**：`10_構成と表記のルール.md` の「7. 仕上げのチェックリスト」で確かめた結果を短く書く

## 出力の形（2回目：スライドを作ったあと）

```
（1行で：どのひな形で、何枚のスライドを作ったか）
スライド：（URL）

## 確認してほしいこと
- 置いた前提：
- 資料に無く空けた数値：
- 制作側で作った言い回し：
- 文字が枠からはみ出していないか、言葉の途中で折り返していないか、ロゴの位置が合っているか
- 似た配置の枚（カードが並ぶ枚）が続いていないか、背景・カード・表の地の色が塗られていない所がないか
- 講座・特典の日付・料金・条件が要項と同じか（制作側で足したワーク・言い回しはノートに「台本には無い」と書いた）

出典: （読んだ資料）
```
