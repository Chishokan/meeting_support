# 作業の手順書 使い方

智翔館AIに「チラシを作って」「この資料をチェックして」のような短い頼み方で作業を終えてもらうための手順書。
画面の「よく使う作業」のボタンは、このフォルダのファイルから作られる。**ファイルを足すと、ボタンとAIの作業が増える**（コードの変更は不要）。

## 書き方

- 1作業1ファイル。ファイル名は `10_チラシを作る.md` のように番号を付ける（番号の順にボタンが並ぶ）
- **ルールそのものは書かない。** ルールは各 `00_使い方.md`・テンプレート・チェックリストにある。手順書には「どれを読むか」「何を聞くか」「どの順に進めるか」「何を出すか」だけを書く
- 数字・日付・料金は、確定した要項（`40_要項/` で status が「確定」のもの）からだけ取る、と手順に書く
- 資料づくりの手順書では、出力の最後に「確認してほしいこと」（置いた前提／要項に無く空けた項目／制作側で作ったコピー）を必ず入れる

## front matter

ほかのナレッジと同じ項目（title・dept・owner・updated・summary など）に加えて、次を書く。

| 項目 | 中身 | 例 |
|---|---|---|
| `task` | 作業の名前（英小文字とハイフン） | `flyer` |
| `button` | 画面のボタンの文字 | `チラシを作る` |
| `starter` | ボタンを押したときに入力欄に入れる文の例 | `冬期講習（中3）のチラシを作って` |
| `use_when` | どんなときに使うか（AIと職員に見せる） | `チラシ・ポスター・サイネージを新しく作るとき` |
| `reads` | 手順書と一緒にAIに渡す資料（knowledge/ からのパス） | `[35_広報・制作/チラシ制作/00_使い方.md, …]` |
| `must_include` | 回答に必ず入れる見出し。無いと画面に注意が出る（資料づくりだけ） | `確認してほしいこと` |

- `reads` に入れた資料も、確定していない要項や名前が `_` で始まるものは渡されない
- `reads` は合計8万字まで。超えた資料は名前だけ伝わり、AIが必要なら開く
- このファイル（`00_使い方.md`）には `task` が無いので、ボタンにはならない
