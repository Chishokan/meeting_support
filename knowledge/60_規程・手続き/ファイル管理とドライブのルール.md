# ファイル管理とGoogleドライブのルール

2026年8月22〜26日にシステム担当（安藤）がマイドライブとPC内を棚卸しし、そのときに決めたルール。
出典：docs/10-file-management.md・11-google-drive.md・12-workflow.md・13-environment.md。

## 1. 置き場所の役割

**同じファイルを2か所に置かない。** 迷ったら下の表に従う。

| 場所 | 置くもの | 置かないもの |
|---|---|---|
| Googleドライブ | 生きているデータ（スプレッドシート・フォーム・回答集計・名簿・議事録・時間割）、共同編集するもの、職員に共有するもの、**個人情報を含むもの** | 制作の作業ファイル、完成した重いファイル |
| 制作担当のPCの作業フォルダ（`chishokan/`） | ルール、制作作業（コード・HTML・コピー原稿・プロンプト）、過去資料の棚（`library/`） | 個人情報を含むファイル、共同編集が必要なもの |
| Dropbox | 完成素材の共有保管（写真・動画・ロゴ・完成PDF、Adobeのプロジェクトなど大容量） | 作業途中のファイル |
| Canva | デザイン制作中のデータ | — |
| Downloads | 一時置き場のみ。**常にゼロを目指す** | 保存したいもの全般 |

- 職員が見るものは、最初から Google 形式（スプレッドシート・ドキュメント・スライド）で Drive 上に作る。PCで作ってから手でアップロードしない（どちらが最新か分からなくなる）。

## 3. ファイル名の付け方

```
YYYYMMDD_案件名_内容_v1.拡張子
```

| 要素 | ルール | 例 |
|---|---|---|
| YYYYMMDD | 作成日。8桁・区切りなし | 20260912 |
| 案件名 | 案件フォルダ名と同じ語 | 秋講座LP |
| 内容 | 何のファイルか | ヒーローコピー、KPI表 |
| v1 | 版。連番のみ | v1、v2、v3 |
| 区切り | アンダースコア `_` のみ | スペース・全角スペースは使わない |

- 確定版だけ `v1` を外して `_納品` を付け、納品フォルダに置く（例 `20260915_秋講座LP_LP全体_納品.html`）。
- Google形式のファイルも同じ（例 `20260821_中3チャレンジ合宿_アンケート集計`）。

### 使ってはいけない語

`最終` `最終版` `【修正版】` `【改】` `改` `新` `のコピー` `無題` `Untitled` `テスト用`（原文は「テス用」〔要確認：誤記か〕）

理由：棚卸しのとき、同じ名前のレポートが5件、「のコピー のコピー」が4世代、同名の配布計画が4件並んでいて、開かないとどれが最新か分からなかった。

### その場でやること

- 「のコピー」ができたら、その場で名前を付け直す。
- 「無題のスプレッドシート」を作ったら、閉じる前に名前を付ける。
- Googleドキュメント・スプレッドシートで版を残したいときは、ファイルを複製せず Googleドライブの**変更履歴**を使う（画像・動画などのファイルは下の「版の残し方」）。

### 集計ファイルは版を増やさない

```
NG: 集計.xlsx / 集計_v2.xlsx / 集計_4校舎統合版.xlsx / 集計_再スキャン反映版.xlsx
OK: 20260821_中3チャレンジ合宿_アンケート集計（1ファイル）
    └ シート: raw / 校舎別 / 統合 / グラフ
```

## 4. 個人情報の扱い

- 生徒個人が特定できるファイル（名簿・成績・出席・合格設計図など）は `07_名簿成績出席/`（限定共有）に入れる。マイドライブ直下や共有の広いフォルダに置かない。
- 棚卸しでは、生徒名をファイル名に含むファイルが直下に置かれていた。ファイル名にも生徒名を入れない〔要確認：個人を区別する必要があるときの付け方（イニシャル・ID）〕。
- 制作担当のPCには個人情報を残さない。2026年8月26日、PC内の成績関連ファイル207件を整理し、個人情報を含む56件をDriveの限定共有フォルダへ移した。
- 模試・定期テスト・入試結果は、限定共有のデータベースにまとめてある（Drive `07_名簿成績出席/成績DB/`）。LP掲載候補（伸び・高得点・合格）を引くときもここを使い、個人名は載せない。使い方はシステム担当に聞く。

## 5. 消さずに移す

- ファイルは削除しない。共同編集者が参照している可能性があるため、移動と名前の付け直しにとどめる。
- 重複は `99_アーカイブ/重複_要確認/` へ移す（ゴミ箱に入れない）。削除は中身を確かめてから本人が判断する。
- 「のコピー」で終わるファイルも重複候補として同じ場所へ退避する。

## 6. 職員への共有の流れ

```
Drive上に Google形式で作る（該当カテゴリのフォルダの中に）
  ↓
共有リンクを取る
  ↓
LINE WORKS に貼る
```

- AI（Claude）は LINE WORKS に投稿できない。AIは「共有リンク」と「LINE WORKSに貼る文面」までを用意し、投稿は人が行う。

## 7. 案件の進め方（制作担当）

広報制作の案件フォルダ（`work/YYYY-MM_案件名/`）・README・命名・確認の流れは `35_広報・制作/00_制作の進め方.md` を見る。ここでは全体の流れだけ書く。

壁打ち（保存しない）→ 案件フォルダを作る（**飛ばさない**。READMEに目的・ターゲット・期限・KPI・Drive/DropboxのURLを先に書く）→ 制作 → `_納品` を付けて `03_納品/` へ → 実施 → READMEに実績、確定した数字を台帳へ → 案件フォルダを `library/` へ移す。

- 版の残し方は種類で分ける：画像・動画・音声・pptx などのファイルは v1・v2… と上げるか、差し替えた素材に `_旧` を付けて前の版を残す（`35_広報・制作/00_制作の進め方.md` と同じ）。Googleドキュメント・スプレッドシートは複製せず変更履歴を使う。

## 8. 定期的にやること

| 頻度 | やること |
|---|---|
| 都度 | 保存する前に置き場所を決める。Downloads に残さない |
| 週1（金曜など） | Downloads を空にする。ファイル名の規則違反がないか確かめる |
| 月1 | Drive直下に溜まったものを振り分ける |
| 案件終了時 | `library/` へ移し、README に結果とKPIを書く |
| 年度末 | 前々年度の分を `archive/`（Driveは `99_アーカイブ/年度別/`）へ |

- 振り分け・命名チェックには制作担当のPCにスクリプトがある（既定は計画だけ出して何も動かさない。削除はしない）。使い方はシステム担当に聞く。

## 10. 未解決の課題
