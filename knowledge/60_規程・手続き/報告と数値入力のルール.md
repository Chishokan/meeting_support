# 報告と数値入力のルール

時点：2026年11月4日。「決定」と「提案・試行中」を区別して書く。

## 1. 数値入力の一本化（2026/09/01 決定）

| 数値 | 変更前 | 変更後 |
|---|---|---|
| 生徒数 | 校舎長が集計表に手入力 | 入力廃止。生徒マスタ（ステータス＝会員）から毎日自動集計（毎朝6時に校舎×学年の在籍数を記録） |
| 売上目標・実績 | 校舎別シートが散在 | 予算入力フォーム（月次・毎月5日締切） |
| 生徒数目標 | なし | 予算入力フォームで一緒に入力 |

- 理由：数えれば出る数字を二重に手入力していたため、集計表が2026年4月で更新が止まり、内訳と「計」がずれていた校舎があった。
- 校舎長がやること
  - 入退会があったら生徒マスタを直す（それだけで生徒数は自動で出る）。
  - 毎月5日までに前月分を予算入力フォームに入れる（対象年月／校舎／売上目標／売上実績／生徒数目標／確定か速報か）。
  - 間違えたら同じ月をもう一度出す（最新の提出を使う）。
  - 分からない数字に0を入れない（0は「0だった」の意味になる）。空欄のままにして備考に理由を書く。
  - これまでの集計シートへの入力は止める。旧ファイルは移行確認後に閲覧専用にする（編集権限を残すと元に戻る）。
- 〔要確認〕導入状況：GAS 2本は2026/09/01時点で未実行。設定に無い校舎IDは丸ごと集計から漏れる（当初の設定は一部校舎のみで、早岐・佐々・RED・ネクスタの校舎IDが未設定）。RED日野・RED佐々の正式名称、ネクスタを駅前・日野に分けるかも未確定。

## 3. 未集計・未定・時点の書き方

- データが無い項目は空欄にせず「未集計」と書く。推測で埋めない（`10_理念・方針/COMPANY.md` と同じ）。
- 決まっていない項目は「未定」、記載が元資料に無い項目は「未記入」と書き分ける。空欄は「記載なし」か「まだ決まっていない」か区別できない。
- 数値には集計時点と集計条件を併記する（例：「2026/10/29時点・朝の回のみ」）。同じ事業でも条件で数値が変わる（例：おはよう勉強会の夏の実人数 238／204／201名）。
- 未報告の件数を書く（実績が低く出ている可能性を示す）。
- 対外の数値は正の集計を1つ決め、送付物どうしでそろえる（`30_部門/地域連携・外部実施.md`）。
- 冬期報告に向け「必須入力項目・単位（％か残り人数か）・未集計時の書き方」を1つに決める提案あり（9/10会議）〔要確認：決定内容〕。

## 4. 月次実行計画の評価（試行中、2026/10/20〜）

位置づけ：各部門の月次実行計画を安藤が評価し、社長に報告する（冬期要項の評価と同じ形）。まずClaude Codeのスキルで回し、実用が見えたらアプリ化を検討。

### 決めたこと（2026/10/20〜21）

- 目的：課題をシンプルに浮き彫りにし、客観的で会社方針に沿ったアドバイスで各部門が動きを修正・効率化する。
- 前月タスクの実行率に自己申告は使わない（主観で評価がぶれる）。普段の報告事項から拾い、報告がない要件は「実行していない」または「報告する姿勢がない」としてマイナス評価。
- 評価基準は2層：①観点（全部門共通・少数）②報告要件チェックリスト（部門×月ごとに出ているべき報告・数字・行動。報告がなければ自動でマイナス）。
- 採点：100点満点（B・Fは15点、他は10点）。小項目ごとに3段階（満点／半分／0）。同じ欠落は観点ごとに重ねて減点。端数は切り捨て。合格目安80点／60点は仮。

### 観点（v2・2026/10/21）

| 観点 | 見ること |
|---|---|
| A 数字で現状をつかんでいるか | 在籍・入会・体験・退塾を実績・目標・昨年で、学年別に。無い項目は「未集計」 |
| B 前月の約束を果たしたか | 前月の計画・決定事項・定例を今月の報告と突き合わせる。報告がなければ未実行 |
| C 未達の原因と次の手 | 原因が仕組みレベルか（各論・天候・生徒事情で終わらない）。担当・期限のある次の手 |
| D 計画の具体性と重点 | いつ・誰が・何を・どのくらい。週次に分解。重点3つ以内。年間サイクルの先読み |
| E 募集と継続 | 紹介→名前上げ→問合せ→即日面談→体験→入会の数と率、次の約束、行動量の計画対実施。講習後の継続・内部受講・持ち上げ |
| F 定期テスト・評定アップの対策 | 生徒別の目標点・評定目標、テスト日から逆算した行動（2週前・10日前・1週前）、全学年が対象か（特に中3）、結果の回収・分析と次の手 |
| G 方針・理念・連携 | 割引に頼らない・高付加価値、理念の柱と夢・志、他部門・NEP・社内資源、横展開、やらない選択 |
| H 報告の姿勢と体制 | 期限内提出、数字の欠け・重複、困りごと・ヒヤリハットを出す、協議は決定で閉じる。人員・育成・負荷 |
| I 社内制度との整合 | 社内の制度の期限・対象に目標と行動がそろっているか（制度の内容はこのナレッジの対象外） |

- 保留：採算（売上データが入っていないため）。
- 一般に必要で智翔館の様式に弱かった点として、退塾（解約）の数と理由を観点Aで見る。

### 報告要件チェックリスト（10月の例）

| 部門 | 10月に出ているべきもの |
|---|---|
| 小中等部 | 秋期県一斉の外部動員、テスト対策の外部、冬期DM準備、サイトク |
| RED個別 | 中3提案数会議、増コマ提案数会議、仕上がった後の対応表会議、模試分析、冬期の動員目標・門配計画 |
| 高等部 | 保護者説明会（動員80%）・保護者面談（60%）、冬期招待リスト、12/1継続の見込み |
| 全部門 | 月次数値の入力、月次報告の提出 |

- 英検・LEC・総務・NEPの定例はほとんど取れていない（担当者への聞き取りが必要）。
- 9月の月次報告が会議事前報告に見当たらない部門・教室があり、現状でも「報告なし」の判定が多く出る（2026/10/21時点）。

### 評価報告の型（社長報告、Word）

1. 評価（点数／100点）と前回からの変化
2. 課題と次の行動：課題ごとに「問題 → 事実 → 次の行動」
3. 良い動き（加点の根拠）
4. 担当者が次に動くこと：重要な順に3つ（やること・進め方のアドバイス・期限案）
5. 期日の目安（逆算・案）
6. ご判断いただきたいこと
- 運用ルール：次の会議の冒頭で前回決定の完了・未完を全件報告する。次回会議の日程は会議の最後に必ず決める。
- 表現は和らげ、次の行動と期日を厚くする（2026/11/04の修正方針）。実施前の企画書は、講習後の運用を詰め切っていなくても減点しない。

## 5. 要項テンプレートの取り込みの決まり（2026/09/12）

書くときの原則（塾生／一般生、税込、年つき日付、未定の書き方など）は `40_要項/_TEMPLATE_有料講座.md` にある。ここでは取り込み・確定の手順だけ。

- 記入はGoogleドキュメント「_要項テンプレート（記入用）」でタブを複製して行う。
- 本文に見出し1を使わない。取り込みスクリプトは太字でない「# 見出し」をタブ区切りとして1件1ファイルに割るため、本文の見出し1が別要項として切り出される。
- Googleドキュメントの Markdown 取り込みは改行を詰める。記入欄はすべて箇条書きにし、各行に「（例：…）」を入れて行が残るようにする（空の箇条書きは消える）。
- ＜基本情報＞の「作成者」「ステータス」は取り込み時に front matter の owner／status へ転記する。status は元資料が「案」で未決事項を含むものだけ「下書き」。
- 確定前チェック（`check-yoko.mjs`）の必須項目：対象・日程・受講料・申込開始日・申込期限・申込方法・支払い方法・連絡先。
- ＜経理連絡事項＞（請求対象・請求方法・引き落とし日・締日・計上月・教材費・合宿費・返金規定・申し送り）を担当者が選ぶだけで埋まる形にした。
- 2026/09/12に旧要項24件をテンプレート形式に変換。元データに記載のない項目は「未記入」と明記。曜日は2026年のカレンダーで検算。
- 変換時に見つかった元データの不整合（〔要確認〕）

| 要項 | 内容 |
|---|---|
| 2026-07 夏期 小等部 | 後期「50分×3コマの計21コマ」と内訳15コマが不一致。塾生／一般生の区分なし。実際の実施（5,500円・全8コマとする資料あり）と食い違い（`30_部門/冬期講習の設計.md`） |
| 2026-07 夏期 中等部 | 時間帯の記載が中1・2のみ。中3への適用が不明 |
| 2026-03 春期 中1 | 日宇校・大野校「3/31〜4/3の5日間」（4日間） |
| 2026-03 春期 中2・3 | 塾生特典の検討メモが残っている |
| 2026-02 TOP10スタートアップ 日野校 | 塾生／一般生の区分なし |
| 2026-04 県中受検対策セミナー | 時間帯「検討中」と「13:30〜15:00」が併記 |
| 2026-05 2026体験パック | 「5・6月体験キャンペーン」とほぼ同一。どちらを正とするか |

## 6. AIで社内データを扱うときのお願い（2026/10/24〜）

AI利用の全体の考え方・入れてはいけない情報は `60_規程・手続き/AI利用のルール.md`。ここは2026/10/24の職員向け説明文で決まった当面の運用だけ。

- 生徒数・売上・目標の集計や分析は安藤に依頼する。各自でAIに数値を貼って分析しない（職員の社用アカウントが整うまでの当面の運用）。
- スプレッドシートのURLを転送しない。見せたい人がいるときは、シートの持ち主か安藤に「相手を指定した共有」を頼む（「リンクを知っている全員」は避ける）。
- 異動・退職する人がいたら、共有から外すために安藤へ連絡する。
- 分析用のAI環境では、個人情報フォルダを設定で開けなくし、共有設定の変更はAIにさせず人が行い、メール送信・Web公開は毎回人が確認してから実行する。画像・動画生成などの外部サービスは分析作業ではつながない。社外と共有しているフォルダは保存先にしない（2026/10/24 設定完了）。
- 今後：AIの学習設定オフ（Claude・ChatGPT）、PCの暗号化、分析で使うシートの共有設定の見直しは実施予定。職員の社用アカウント（Google Workspace）の導入は経営判断待ち〔要確認〕。
- 残るリスク：データが職員個人のGoogleアカウントの持ち物になっている。名簿・成績の置き場所は別途見直し。

## 7. 分析資料の匿名化（模試・アンケート分析の共通ルール）

- 氏名と成績を分けて持つ。分析はIDだけのデータで行い、氏名は最後の工程で差し込む。
- 共有用（ドキュメント・HTML・提携先向け）には生徒の氏名を入れない。校舎＋連番や匿名記号に置き換え、対応表は restricted で管理（配布しない）。
- 氏名入りのファイル（名簿・要対応リスト・未提出者タブ）は `07_名簿成績出席` など限られた場所に置き、共有範囲に注意する。
- 少人数の区分の平均は個人が特定されうる。1名だけの区分は「その他」に合算する。
- 生徒の声は学年・時期だけを付けて載せる。
