# AI利用のルール

出典：制作・システム担当の作業ルール（docs/08-ai-operations.md・07-development.md・12-workflow.md・13-environment.md、2026年8月）と、既存ナレッジに散らばっている決まり。
〔要確認〕正式な社内規程としての「AI利用規程」は未入手。ここは運用上のルールのまとめ。

## 1. 基本の考え方

> 分析・アイデア出しは AI に。
> 選ぶ・決める・実行するのは人間。

- AIは文章を作る道具ではなく、**業務改善の道具**として使う。
- 生徒・保護者に関わる判断（成績の見立て、進路のアドバイス、面談の方針）はAIの案を参考にして、人が決める（「分析はAI、決めるのは人間」）。

## 2. 対象にしている業務の例

| 分野 | 例 |
|---|---|
| 会議 | 会議準備、事前報告の整理、議事録 |
| 募集・分析 | 集客分析、校舎分析、データ分析 |
| 制作 | 広告制作、LP制作、スライド、社内資料 |
| 指導 | 生徒指導の支援、教材作成、AI学力診断・アドバイス生成 |
| 保護者 | 保護者対応の文面づくり |
| 研修 | 社内研修 |

## 3. AIに入れてはいけない情報

| 入れないもの | 補足 |
|---|---|
| 生徒・保護者の個人情報（氏名、連絡先、成績の個票） | 生徒を区別するときは ID や匿名化した属性（学年・学校の区分など）だけ。文書では生徒名をイニシャルにする（`10_理念・方針/COMPANY.md`） |
| パスワード、APIキー、アプリケーションパスワード、サーバーのログイン情報 | AIに渡さない・書かせない・チャットに貼らない。ログインは本人が行う（`35_広報・制作/Web制作/00_使い方.md`） |
| 給与、人事評価、健康情報 | AIナレッジにも入れない（`00_index/README.md`） |
| 売上・利益などの業績数値 | 目的外の資料に入れない（`35_広報・制作/スライド制作/00_使い方.md`） |

- AI研修では、このルールを**最初に**示す。

## 4. AIの出力を使う前に人が確かめること

- AIの出力は、**必ず人が確認してから**生徒・保護者に渡す。
- 数字・日程・料金はAIに作らせない。確定した要項・元データから写す。AIが出した数字は元資料と照合する。
- 出典を示せない情報は使わない。推測で埋めない。不明な点は「未定」「〔要確認〕」と残す。
- 決裁者コメント欄はAIに書かせない（空欄のまま残す）。
- 実在の人物（講師・生徒・社長）の画像は生成しない。
- 公開・配布・送信（Webの公開、LINE WORKSへの投稿、保護者への送信、フォームの送信テスト）は人が行う。

## 5. ツールの使い分け

| ツール | 主な用途 |
|---|---|
| Claude | 企画、文章、コード、資料、ファイル整理（社内の主なAI） |
| ChatGPT | 画像生成（`35_広報・制作/画像生成AIの使い方.md`）。LP案の叩き台を作らせた例もある |
| Canva | ChatGPTの出力の調整、文字組み |
| 社内AIアシスタント（このナレッジを読むAI） | 社内ルール・要項・数値の質問への回答（`00_index/CLAUDE.md`） |

### チャットと Claude Code の使い分け（システム・制作担当向け）

基準：**保存して後で探すものなら Claude Code、その場で考えるものならチャット。**

| Claude Code | チャット |
|---|---|
| LP・HTML・CSSの制作、GAS・スクリプト開発、コピー・構成案の確定稿、データ集計・分析、Driveの整理・ファイル作成、繰り返す定型作業 | 企画の壁打ち・アイデア出し、画像生成（チラシ・ポスター案）、外出先での確認、同僚に見せる資料（共有リンク） |

- チャットの出力を手でコピーして手で名前を付けて保存する運用が、ファイルが散らかる原因になっていた（`ファイル管理とドライブのルール.md`）。
- Claude Code は作業フォルダ（`chishokan/`）で起動する。ほかの場所で起動すると社内の規則ファイルが読み込まれない。

## 6. 開発でAIを組み込むとき（システム担当向け）

- APIキーをアプリ・Webページ（利用者側）に埋め込まない。
- 生徒個人が特定できる情報を外部のAI APIに送らない設計を優先する。
- スプレッドシートIDなどの設定値はコードに直接書かない。
- 現場の担当者がそのまま使えることを優先し、余計な仕組み（外部ライブラリ・ビルド環境）を増やさない。既存の機能を壊さないことを最優先にする。
- 納品するときは、現場向けの使い方（3〜5ステップ）、設定が必要な箇所の一覧、想定される失敗と対処を添える。

## 7. AI研修の設計

- 高等部・中等部・REDなど、**グループ単位**で実施することがある。
- 抽象的なAI論ではなく、**その日の業務で使えるプロンプト**を持ち帰らせる。
- 参加者が自分の業務でその場で試す時間を必ず入れる。
- 個人情報を入力しないルールを最初に明示する。

## 8. NEP事業としての展開

- 社内で実践 → 効果を検証 → 学校・塾・自治体への支援メニューにする、という流れを意識する。
- NEPの第36期の柱（智翔館ナレッジ開発・支援ノウハウの他社販売）は `30_部門/NEP_第36期計画.md`。
